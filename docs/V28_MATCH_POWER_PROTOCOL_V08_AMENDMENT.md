# V2.8 match and power protocol amendment v0.8

## Trigger and endpoint

DEV10's five Connect4 6x7 roots at scheduled plies 5–11 all passed the independent two-ply rule differential, but none returned a complete exact root action-value map under 500,000 nodes, a 500,000-entry cache, and two seconds per root. This shows only that the tested roots were unresolved under that exact budget; it does not establish intrinsic exact-solver infeasibility. The exact-regret primary is paused for this schedule while a whole-game endpoint is evaluated. See `docs/validation/V28_ROOT_ORACLE_DEV10_PILOT.json`.

For game `g`, model-seed checkpoint `k`, comparator `c`, and paired random match seed `m`, let `S⁺` and `S⁻` be the JEPA score (win 1, draw 0.5, loss 0) when assigned the two colors in the two swapped games. Define one paired block as `d[g,k,c,m] = (S⁺ + S⁻)/2 - 0.5`; the comparator's score is `1-S` in each zero-sum game. Thus `d=0` is equal score, and positive values favor JEPA. The primary contrast for each control is the equal-weight average of the Connect4 and Reversi mean `d`. The controls are task-value latent dynamics and direct exact-leaf value, selected before any learned outcome. For the primary standard error, first average the two games within each `(checkpoint_seed, match_seed)` block; estimate each checkpoint stratum's sample variance across its 120 match seeds; then calculate `SE = sqrt(sum_k(s_k^2 / 120) / 20^2)`. For each control, test the one-sided boundary null `H0: D <= 0.05` using `z=(D_hat-0.05)/SE` and the upper tail of the standard normal. Apply Holm step-down to the two resulting p-values at family-wise alpha 0.05. Also report one-sided Bonferroni simultaneous lower bounds `D_hat - z_(0.975)*SE` for both controls. The confirmatory analysis script is implemented at `tools/v28_match_analysis.py`; it validates full schedule coverage, rejects selective censoring, counts model forfeits as scored outcomes, applies the stated stratified standard error and Holm test, and reports seed sensitivity. Focused tests cover these rules. Commit and record its SHA-256 together with the frozen schedule before training and before outcomes are read; evaluator/runtime/power gates remain outstanding, so this protocol is not yet fit-ready. The +0.05 margin means JEPA scores 0.55 rather than 0.50 on average (five additional game points per 100 games above draw-even; equivalently a +0.10 score differential between the two zero-sum players). This is a declared practical threshold for this pilot study, not a threshold inherited from prior literature. An independent review must retain or revise it before any fit. Report each game, color, checkpoint seed, and control separately.

The practical superiority margin is frozen at +0.05 on `d`. The primary pass rule is Holm-adjusted one-sided `p <= 0.05` against the margin for both controls; report the one-sided Bonferroni simultaneous lower bounds as conservative uncertainty intervals. For game `g`, define its estimate as the mean of `d[g,k,c,m]` over checkpoint seeds `k` and match seeds `m`. For color `+` or `-`, replace each pair's `d` with that color's individual JEPA score minus 0.5 and average over the same seeds. For checkpoint `k`, define its guardrail aggregate as the equal-weight mean over the two games and both colors, averaged over its 120 match seeds. To prevent a favorable pooled mean from hiding regressions, each game-specific and color-specific mean must be at least -0.02; no more than 5 of the 20 checkpoint-seed aggregates may be below -0.10 and none may be below -0.25. These are predeclared heterogeneity guardrails, not separate hypothesis tests. If the independent method review rejects these thresholds, issue a new protocol version before fitting; do not revise them after viewing learned results.

## Match schedule and opponents

Each paired block uses the same initial state, tie-break seed, model seed, and opponent/control configuration, then swaps player colors. Keep all starts, legal moves, full transcripts, terminal outcomes, time/node counts, and hashes. The primary head-to-head schedules compare the learned arms directly. A fixed secondary robustness league covers the project-owned uniform-legal, tactical, positional, and bounded-search policies in both colors. The league does not represent a calibrated opponent distribution or worst-case/exploitability measurement. Any model-specific timeout or budget overrun is a forfeit/loss in that model's outcome, not a censored block; only an external failure affecting every arm can censor the full pair.

Use 20 fixed checkpoint seeds `(17, 29, 43, 59, 71, 83, 97, 109, 127, 139, 151, 167, 181, 197, 211, 227, 241, 257, 271, 283)`. These checkpoints are a finite panel; the primary inference is explicitly conditional on this panel. Report seed-to-seed variation and a hierarchical bootstrap over checkpoint seeds as a sensitivity analysis, but do not claim population-level training-seed generalization from a finite panel. Generate 120 independent match seeds for each checkpoint seed, game, and comparator, for 2,400 paired blocks per game/control and 9,600 paired blocks total. Each block contains both color-swapped games. Match seeds are disjoint from data-generation seeds and independent across checkpoint-seed strata. Before any development fitting, publish the schedule/code commitment hashes, evaluator version, legal action and timeout rules, block count, color swap, multiplicity correction, external-failure rule, and stopping rule. Keep the final outcome file sealed from checkpoint selection. An illegal action is a loss; a model-specific timeout is a forfeit/loss. Only external process/infrastructure failure that prevents all compared arms from producing an outcome invalidates and censors the whole paired block; report counts and reasons. For any rule mismatch, incorrect replay, or nondeterministic replay, halt the entire evaluation, retain all raw outputs, and invalidate the study version. Fixing the implementation requires a new version and a completely fresh locked schedule before any confirmatory run; do not selectively rerun or censor blocks. No replacement blocks may be added after viewing outcomes.

## Power gate

Use the frozen nonlearned match schedule to verify rule correctness, runtime, paired-block variance, seat effects, and external censoring. For conditional-on-panel power, use the disclosed normal approximation `n = ceil(((z[1-alpha/(2J)] + z[0.80]) * sigma / (delta - margin))^2)`, with `J=2` primary controls, family-wise `alpha=0.05`, and `delta>margin`. The required-block table targets 80% **marginal power per comparison** at a conservative Bonferroni threshold; it does not assert 80% joint power. The schedule code also reports per-comparison power at the planned `n=2,400` and the dependence-free union-bound lower bound for both controls passing: `max(0, 1 - sum_j(1-power_j))`. This bound is conservative and requires no independence between control outcomes. Evaluate paired-block SD `sigma` in `{0.25, 0.40, 0.50}` and true effect `delta` in `{0.10, 0.15, 0.20}`; the corresponding excesses over the +0.05 margin are `{0.05, 0.10, 0.15}`. The 0.50 maximum is the mathematical bound for `d`; no infeasible SD value is used. At the conservative feasible planning corner `sigma=0.50, delta=0.10`, the formula requires 951 independent paired blocks per game/control; the frozen plan provides 2,400. The normal approximation and assumed common scenario effect/SD are planning assumptions, not measured data. This calculation is conditional on the 20-checkpoint panel and does not power generalization over all possible training seeds. Report hierarchical-seed sensitivity separately. Price the complete nonlearned schedule on local hardware; the prefit schedule/power gate is capped at four CPU-hours. This is model-blind scenario analysis, not evidence of JEPA effect. If measured runtime exceeds the cap, or the observed nonlearned variance invalidates the scenario assumptions, stop and amend the protocol before any fit. Do not use cloud/GPU services or spend money without separate authorization.

Training and match comparisons charge model inference, game transitions, and search under the same declared wall-clock and node limits. Report an equal-update track and an equal-measured-compute track. Freeze one policy for each model seed using validation/selection only; no confirmatory match, locked root, or final schedule can influence training, hyperparameters, architecture, or checkpoint choice.

## Interpretation and stop rules

This endpoint tests whole-game performance against specific matched controls in two named deterministic synthetic-data games. It does not estimate minimax regret, behavior-policy likelihood, equilibrium, exploitability, or strength against all legal/adversarial opponents. Retain exact-root regret only as a secondary complete-case diagnostic with every scheduled unresolved root accounted for and no solver-success-only denominator.

Stop or narrow if paired schedule generation is not reproducible, reference agents saturate the games, color effects exceed the preregistered tolerance, power is unattainable, differential censoring occurs, or the JEPA arm fails either same-search control. No development result can be promoted to confirmation. No learned result has been generated under this version yet.
