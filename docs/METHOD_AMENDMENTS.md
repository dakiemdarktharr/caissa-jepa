# Method amendments

## v1.1 — 2026-09-29, before any multi-game code/data/training

Independent design review identified two confounds in frozen v1. Preserve `METHOD_SPEC.md` as the original and apply these amendments to the feasibility implementation.

1. Replace held-out 4x5 connect-4 with **gravity connect-3 on 3x4**. The former exposes wholly untrained fifth-column parameters and connect-target extrapolation in the flat encoder. The new variant stays within trained coordinate/action/rule-descriptor support. It is a held-out **size combination**, not an unseen game family. The original proposal may be a later explicitly labelled extrapolation stress test, never a clean transfer test.
2. Nonempty splits are insufficient. Before training, require per trained game: at least 64 train records from 16 trajectories; at least 16 validation, 16 selection and 16 final records from 8 trajectories each; at least 16 train H2 records and 8 H2 per held-out split. Report retained/raw proportions and early/middle/late phase counts. A split with no early or middle records is flagged as coverage failure for whole-game training claims. Strict held-out-first overlap can remove nearly all tic-tac-toe training data and increasingly damage validation as more trajectories are generated. Do not increase collection blindly or waive the gate after seeing performance.

If the strict full-trajectory pilot fails these support gates, retain the failure and stop dependent training. The next version must redesign disjoint situation/branch collection or narrow the task (for example late-game planning) before fitting. This is a data-feasibility kill criterion, not evidence against JEPA. Do not use final prediction metrics to guide that redesign.

3. The generated pilot can only establish a method scaffold and data feasibility until exact behavioral best-response/complete match studies exist. No NLL/calibration number from observed synthetic actions establishes minimax optimality. Causal opponent-action conditioning does not itself identify a particular opponent model.

4. The legacy chess confirmatory runner is blocked unconditionally until an independent full-history rules validator is actually implemented. User-supplied booleans or pinned UCI telemetry cannot clear that gate. This is a concrete unmet scientific prerequisite, not a generic safety warning.

## v1.2 — data-feasibility pivot, before model fitting or held-out predictions

The v1.1 800-trajectory audit failed its frozen whole-game coverage criterion: tic-tac-toe train and selection have no early-phase records after strict overlap removal. The failed manifest is preserved at `chess_data/two-player-pilot-v1/manifest.json` (fingerprint `c506b7907bc0917addb8478d3ea69331a2db31dbcd7d29c1318efeef901f5dda`). No model was trained from that failed dataset.

Narrow the first feasibility task to **middle/late-game local planning**, defined *before fitting* by root ply / board area >= 1/3 in every game and every split, including transfer. Reversi phase uses played plies (including pass), not occupancy. Exclude early contexts with a distinct scope-exclusion count, then run the same strict overlap and sample-support gates. Require middle and late support instead of early and middle. This is a new immutable dataset version, not reclassification of v1.1 as passed. Do not claim whole-game strength or opening play from it. Selection/final prediction outcomes remain unopened.

Complete objective by variant: all have current-state policy CE + value MSE. Predictive variants add 0.25 times horizon-masked predicted-value MSE at each enabled horizon. `full`, `no-response`, `no-var` add latent MSE for H1+H2; `h1` adds H1 terms only; `decoded` replaces latent MSE with target-feature decoded MSE at H1+H2; `value-dynamics` adds predicted-value losses only. Variance coefficient is 0.1 except direct and no-var (zero). `direct` has no predictor loss. H1 never receives an H2 loss. JEPA versus direct compares the predictive training package, not only latent loss; `value-dynamics` and `decoded` are the relevant controls for that distinction. No claim of exact active-FLOP matching: report active parameters, examples, steps and wall time separately. Same shuffled batches/seeds/epochs are frozen for the first comparison.

Reversi terminates immediately when neither player has a legal placement; a forced pass changes the player but no counter is needed. The representation therefore contains the complete Markov rule state for this rule version. Symmetry-aware audit and rule transformations do not make the affine encoder equivariant.

Pilot run declaration: seeds 17/29/43, 10 epochs, batch64, lr0.001, latent32, seven variants above, shared weights across three training games, one BLAS thread. Evaluate validation only, plus the unchanged-weight held-out size variant in a separately labelled exploratory transfer diagnostic. Fixed diagnostic sample: at most 24 legal nonterminal validation/transfer states per game with <=4 empty cells, selected by SHA order before model scoring. Oracle computes exact minimax action regret; two-ply exact-state and hybrid latent planners use the same legal branches, node cap1024/time cap1s and retain failures. This is a local-position diagnostic, not a match tournament or exploitability estimate. No model-selection or final predictions. A run-level wall-time cap of 180 seconds per model and 1 GB artifact budget are admission limits; actual time/memory are reported. Larger and confirmatory runs remain gated by independent review and resource evidence.

Implementation clarification before fitting: hybrid H1 control recursively applies the same H1 predictor for own action and reply, then evaluates the two-ply value. It is a recurrent H1 inference control and may accumulate rollout error; it is not trained with a two-step rollout loss. Direct uses exact-state re-encoding in both tracks. The fixed schedule deduplicates symmetry-equivalent root positions. Report neural-leaf usage and oracle action gaps to identify terminal-dominated or nondiscriminating diagnostics. Node caps count transitions only; wall-time includes neural calls. Reaching exactly the node cap must not censor completed leaf evaluation.
