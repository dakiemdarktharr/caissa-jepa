# METHOD SPEC V2.12-04: Alternating-Player Multi-step JEPA

Status: draft v04 reviewed on 2026-10-02 and accepted only for the narrowly
scoped no-training instrumentation pilot in Section 8; this is not a training
grant, novelty claim, or superiority result. The fixed 2.0-second search gate has
failed the rule-only Reversi8 p90 audit. No fitting or locked-data evaluation
is permitted until the compute protocol is revised from no-outcome evidence
and independently reviewed. Changes require a new version.

## 1. Falsifiable hypothesis and scope

The study instantiates this hypothesis only on Connect Four and Reversi
adapters, using board-size holdouts within these two game families. It does not
instantiate or establish cross-family transfer beyond them. For deterministic,
fully observed, finite-action, alternating-turn, two-player zero-sum board
games, a latent predictor trained on sequential actions from both roles and
multiple future plies improves the action score from a fixed
four-ply max-min backup heuristic over matched non-JEPA value/dynamics
controls at equal training and inference budgets. The leaf heuristic is
trained on the declared rollout-policy mixture outcomes, not minimax values.
Any gain must persist on board-size variants held out from training.

This method does not predict a particular opponent's behavior. Its policy
head predicts recorded actions pooled across the fixed data-generation policy
mixture, and its dynamics predictor predicts state consequences conditional
on supplied actions. Neither is an opponent-specific model. Its value labels are
terminal outcomes from the fixed synthetic rollout-policy mixture, so the
value head is an empirical mixture-outcome heuristic, not a worst-case game
value and not a calibrated expectation for a named opponent. The planner
alternates max/min at internal legal-action nodes, but its leaf values retain
that behavior-data interpretation. This hybrid is not a minimax-value
estimator, full-game equilibrium solver, or exploitability guarantee. Hidden
information, simultaneous actions, stochastic transitions, and general-sum
utility are outside scope.

## 2. State, action, and value conventions

At ply `t`, exact state is `s_t`, absolute player to move is `p_t in {-1,+1}`,
and legal actions are `A_g(s_t)`. The deterministic rules adapter is
`T_g(s_t,a_t)=s_(t+1)`. Its terminal function returns absolute winner
`w_g(s_T) in {-1,0,+1}`, matching `BoardGame.terminal`; utility for player `p`
is `u_g(s_T,p)=p*w_g(s_T)`. The 198-dimensional `x_g` encoding uses
side-to-move-relative pieces and a game descriptor. Action ids use the shared
65-entry 8x8-grid vocabulary. Connect Four and Reversi use one shared
encoder/predictor/value checkpoint, with no game-specific learned weights.
Exact transitions generate targets and search children. Adapters validate
legal actions, terminal utility, deterministic transitions, role alternation
and forced passes.

The online encoder is `z_t=f_theta(x_g(s_t,p_t)) in R^32` with tanh output.
The target encoder `f_theta_bar` is an EMA copy with stop-gradient. A shared
transition predictor consumes latent state, absolute actor role `p_t`, one
legal action `a_t`, and game descriptor `g`:

    zhat_(t+1) = F_phi(zhat_t, onehot(a_t), p_t, g)

Freeze the encoder as one affine map `198 -> 32` with tanh; policy and value
heads are affine `32 -> 65` and `32 -> 1`, with tanh on value. `F_phi` is one
affine map from the concatenated `32+65+1+6` input to `32`, with tanh. The six
descriptor values are `x[192:198]`; player role is the scalar `p_t`. Every
arm has the same encoder and heads, and each predictive arm has the same
predictor shape. Initialize each weight matrix independently with
`Normal(0,1/sqrt(fan_in))`, biases zero, paired across arms by seed. Update
target encoder after each online optimizer step as
`theta_bar <- 0.99*theta_bar + 0.01*theta`. No target projector, decoder
pretraining, or game-specific parameters are used outside the explicitly
named raw-state control.

Initialize `zhat_t=z_t` at the root and apply the predictor recursively without
re-encoding exact intermediate states. Actor role alternates explicitly. A
Reversi forced pass (action id 64) is an ordinary valid transition. Terminal
states receive exact utility and never an approximate latent value.

The policy logits are masked by `A_g(s_t)`. The value head `v(z_t) in [-1,1]`
reports utility for the side to move. At nonterminal leaf depth `d`, root
utility estimate is `V_root(s_d)=p_0*p_d*v(z_d)`. A terminal leaf is
`V_root(s_T)=p_0*w_g(s_T)`. All action values and paired outcomes use this
single root-player perspective. Rule tests must pin absolute winner, draw,
color swap, and side-to-move sign conversion.

## 3. Candidate JEPA objective

Training examples are train-only trajectory windows of up to four plies,
`(x_t,p_t,a_t,...,x_(t+4),p_(t+4))`, generated by the exact adapter from
project-owned self-play and scripted-policy episodes. For each sampled window,
the only JEPA targets at `k=1,2,4` are exact states on that same recorded
action sequence; no counterfactual branches are enumerated or averaged in the
training loss. Counterfactual coverage is measured in evaluation. The source
policy id is provenance only; no component predicts it as an opponent model.
Episodes are assigned to train/development splits before windows form.
Terminal states mask every later horizon and receive exact terminal utility.

For `k in {1,2,4}`, recursively predict
`zhat_(t+k)=F_phi(zhat_(t+k-1),a_(t+k-1),p_(t+k-1),g)`. Let `m_k=1` only if
every transition through `t+k` is valid and the target is nonterminal;
otherwise `m_k=0`. Define
`L_roll = sum_k(alpha_k*m_k*MSE_k(zhat_(t+k),stopgrad(zbar_(t+k)))) /
sum_k(alpha_k*m_k)`, where `MSE_k` averages latent coordinates and valid
examples at that horizon. Freeze `alpha_1=1`, `alpha_2=0.5`, `alpha_4=0.25`.
Normalize by valid weighted targets per batch and reject a batch with no
valid target.

Each episode draws one policy independently for each seat, uniformly from the
four pinned sources; each assigned policy remains fixed for that episode. For
an episode ending at `s_T` with absolute winner `w_g(s_T)`, define the
recorded outcome label at each nonterminal trajectory state as
`y_t=p_t*w_g(s_T)`. It is the current player's utility under the synthetic
rollout-policy mixture, not a minimax target. Shared task losses are
legal-action-masked mean cross-entropy for the recorded root action and mean
squared error of root value against `y_t`. All predictive arms also use
`L_outcome_roll`, the weighted masked MSE between `v(zhat_(t+k))` and
`y_(t+k)` at nonterminal horizons `k=1,2,4`, using the same `alpha_k` and
valid-example normalization as `L_roll`. If a target is terminal, bypass its
predicted latent/value and use `p_(t+k)*w_g(s_(t+k))` from the adapter; terminal
states retain the adapter's explicit player-to-move field.
Thus target trajectories, outcome labels, masks and policy-action labels are
shared across arms. The JEPA term is computed only along each recorded
sequence; it is not averaged over the legal reply closure. Total candidate
loss is

    L = L_policy + L_root_value + 1.0*L_outcome_roll + 1.0*L_roll
        + 0.1*L_variance + 0.01*L_covariance

Apply the same latent regularizers to root online latents in every arm. Pin
their implementation to V2.8 source commit
`f5f29af1054496943c43520bbdff5f0b253fd8c4`: for centered root latents `c`,
coordinate standard deviation is `sqrt(mean(c^2)+1e-4)`,
`L_variance=mean(max(0,0.1-std)^2)`, and
`L_covariance=sum(offdiag(cov(c))^2)/32`. No coefficient sweep is allowed.
Report every component, valid/invalid target counts by horizon, latent
mean/std, covariance spectrum/effective rank, and gradient norm. Any nonfinite
loss or gradient aborts the run. Logged losses are diagnostics only and cannot
select a model.

Initialize online weights using the pinned seed recipe and target weights from
online weights. For each training game, deterministically select exactly 928
valid windows from train-assigned episodes before fitting; fail the data gate
if either game cannot supply that count. Each epoch visits every selected
window once, shuffled within game, with every minibatch balanced at 32 windows
per game. Thus 1,856 windows make 29 full batches per epoch and exactly 87
updates over three epochs. Each arm and seed uses the
same precomputed per-epoch window order and minibatch boundaries. Paired
initialization randomness may vary by seed, but data order is shared across
arms for that seed. Freeze learning rate 0.001, batch size 64, EMA 0.99, Adam
`beta1=0.9`, `beta2=0.999`, epsilon `1e-8`, and global gradient-norm clip 5.
Resume only when method, code, config, data, runtime, split, schedule and seed
fingerprints all match. Save checkpoints atomically.

## 4. Controls and ablations

All arms use identical episodes/windows, 20 paired initialization seeds,
compatible encoder and policy/value heads, three epochs/87 updates, exact
rules, and development schedule. Freeze these six arms before implementation:

1. **Multi-step JEPA candidate:** objective above; recursive latent and
   rollout-value targets at one, two, and four plies.
2. **Single-pair JEPA:** same trainer, windows and task losses, but latent
   prediction is enabled only at the two-ply point on that recorded
   action sequence; shared rollout-value targets remain at 1/2/4. This matched
   single-horizon arm is not a reproduction of V2.9's counterfactual reply-set
   objective. V2.11 lambda=8 is historical only and will not be refit.
3. **Recursive raw-state dynamics:** shared encoder/predictor trunk and a
   decoder predicting 198-dimensional exact next-state features at one, two,
   and four plies. Re-encode each predicted feature vector before its next
   step. Use masked feature MSE plus the same policy/root/rollout-value losses.
4. **Value-only latent rollout:** same recursive trunk/horizons, trained with
   the same recorded-trajectory outcome labels at predicted horizons plus
   shared task losses. It has no latent or raw-state prediction target and
   receives no extra oracle labels. It isolates latent matching from
   value-only rollout supervision.
5. **Direct-leaf value:** no learned transition predictor; encode the exact
   four-ply leaf for value. It uses the shared policy/root-value losses and
   a value loss on the exact four-ply state from the same window; report its
   extra encoder calls.
6. **Single-horizon JEPA ablation:** same JEPA architecture/trainer with only
   one-ply latent target (while shared value-rollout targets remain at 1/2/4),
   to isolate the multi-step component.

All heads, target masks, horizons, windows, seeds, optimizer, and updates are
fixed across arms. Before a fit grant, record parameter counts and forward /
backward FLOPs per update, then profile training compute on the same dry-run
batches. The panel may proceed only if measured total training FLOPs are within
5% across arms; otherwise revise the controls/config in a new version and
re-review before fitting. Evaluation arms share one node-visit and wall-time
cap; also report exact transitions and model calls because equal node visits
do not imply equal model FLOPs. Do not add or substitute baselines after
outcomes are seen.

A game-theoretic reference is required. Use exact minimax only on explicitly
tractable game/position subsets. For larger games, use a fixed bounded-depth
alpha-beta reference with pinned internal heuristic, source hash and config.
Never call bounded search exact or optimal. This policy labels synthetic data;
it is not a learned opponent behavior model.

## 5. Planner and inference budget

At each root, search to four plies under exact shared game rules. At every
node, maximize if the actor is the root player and minimize otherwise.
Terminal value is `root_player*absolute_winner`; nonterminal leaf value is
`root_player*leaf_player*side_to_move_value`. This is finite-horizon max-min,
not a full-game equilibrium solver. JEPA and value-only arms recursively update
latent; raw-state dynamics recursively predict and re-encode features;
direct-leaf encodes the exact leaf. Receding horizon applies only the selected
root action and replans from the next exact observation.

This search is a max-min backup heuristic, not a minimax-value solver: its
internal nodes optimize over exact legal actions, but its nonterminal leaves
use values supervised on synthetic policy-mixture outcomes. Any disagreement
with worst-case oracle values is measured and reported, never hidden behind
the word minimax.

The provisional cap is 500,000 materialized search-node visits and 2.0 seconds
wall time per move for each arm. A visit is counted upon entering a state,
including root and terminal leaves. Separately count every exact rule
transition call, including a generated child later cut off or used only for
legality. Use identical depth, legal-action
order, alpha-beta rule and move order, tie-breaking, roots, and seat swaps.
Timeouts and invalid moves are forfeits to the other player, remain in primary
analysis, and are never replaced or censored. Report nodes, model calls,
CPU/wall time, peak memory, timeout/forfeit counts, and per-arm compute.

The no-training audit fails this provisional wall cap: rule-only, unpruned
depth-four Reversi8 has p90 6.037 seconds across 16 roots, with 28,009 maximum
nodes. The measured traversal did not include learned-model calls. The
reproducible results and limitations are in
`docs/validation/V212_NO_TRAIN_COMPUTE_AUDIT_01.md`; the ignored script hash
and raw output are recorded there. The older alpha-beta constant-zero
measurement is not compute evidence because equal leaf values caused
atypical pruning. Before any fit, run a fresh no-outcome pilot with
representative random-weight model calls on all variants and arms. Set one
common cap using only those measurements, freeze all node/time/timeout rules
in a versioned protocol, and obtain independent review. A failure means
revise and re-review, not train.

## 6. Data, transfer, and splits

Training variants are Connect Four 6x7/k4 and Reversi 6x6. Held-out-size
variants are Connect Four 8x8/k4 and Reversi 8x8; neither can appear in fit
data, and no variant-specific update is allowed in zero-shot evaluation.

Generate project-owned episodes using four fixed policies: uniform-random,
tactical, positional and bounded-search. For each episode, independently
assign one of these policies to each seat, uniformly over the 16 ordered
policy pairs; thus each seat uses each source with probability 25%. The
generator and each policy's exact code/config hashes must be pinned. A separate
manifest must enumerate every seed, ordered policy pair and episode before
generation, and fix counts from resource measurements before any model fit.
After whole-episode splitting, deterministically select 928 eligible windows
per game using the frozen manifest seed, first choosing an eligible train
episode uniformly and then a valid start ply uniformly. Retain exact actions
through four plies or terminal. Freeze the selected window ids before fitting;
each epoch visits this fixed bank once, with equal game weight in every batch.
Do not reweight, replace, or resample windows after model outcomes. This is
synthetic self-play/scripted data, not human or expert-engine data.

Split whole episodes into train and development/model-selection groups before
windowing. Hash each file and bind rules, generator/source, parser, ordered
policy-pair mixture, counts, variant, split and episode ids. No episode,
window, symmetry transform or trajectory derivative crosses these splits.
Held-out-size states are excluded from training. Locked-confirmatory episodes
are not generated or split in this development phase. After nomination,
generate new episodes with disjoint seeds, assign whole episodes to the
confirmatory split before windowing, and freeze its manifest/schedule under a
separate review. Keep data/checkpoints under ignored
`chess_data/`; do not publish them. Existing DEV09 is not reusable.

## 7. Development metrics and nomination gate

Primary development metric is paired candidate-minus-control head-to-head
game score on a fresh development/model-selection schedule, per held-out
variant and equal-weight macro. These data are not confirmatory. Use 20 model
seeds, at least 40 independently generated reachable start situations per
variant, every one of the five controls, and both color assignments per
seed/situation/control comparison. Start situations are generated and hashed
before any model scores them. No situation or generation seed is reused in
locked confirmation. The sample counts are a fixed exploratory screen, not a
power claim; do not interpret a development interval as confirmatory evidence.

For each of the 15 candidate-versus-control contrasts (five controls by two
variants and macro), compute paired differences after averaging the two seat
assignments within each seed/situation cell. Use a two-way crossed bootstrap
that resamples the 20 model-seed ids and start-situation ids independently
with replacement, retaining paired outcomes; use a fixed public seed and
10,000 replicates. In every replicate, use one resampled seed multiset shared
across variants, resample situation ids separately within each variant, and
compute macro as the equal-weight mean of the two variant contrasts. For
familywise 95% intervals, let `SE_i` be the bootstrap SD of contrast `i` and
`T_b=max_i |(delta_i^b-delta_i)/SE_i|`; take the 95th percentile `q` of
`T_b`. The simultaneous interval is `delta_i +/- q*SE_i`. Also report
ordinary percentile intervals as descriptive only. If any contrast has zero
bootstrap SD, any incomplete cell, or any nonfinite replicate/statistic, the
inferential gate is invalid and nomination fails; never omit or regularize
such a contrast after observing outcomes. For positive-effect tests,
use the centered crossed-bootstrap distribution:
`p_i=(1+count(delta_i^b-delta_i >= delta_i))/(B+1)`. Apply Holm step-down
across the same 15 one-sided tests. Nomination requires both the simultaneous
interval and Holm-adjusted p-value gates to pass. This is exploratory
nomination evidence, not a confirmatory test.

Nominate only if the paired mean is at least +0.05 per held-out variant and
macro against each of five controls; each familywise 95% simultaneous
two-way-cluster interval is wholly positive and each Holm-adjusted one-sided
p-value is below 0.05; all comparisons are complete; there are no forfeits;
and every compute cap passes. Report every comparison, per-game
estimate and failed observation. A failed gate stops this objective family;
do not alter primary metric, horizon, variant, search budget, schedule or
exclusion rule after outcomes are observed.

Secondary metrics: exact/bounded-oracle action regret, minimax action-ranking
agreement, value error/calibration, all-legal policy NLL/MRR, latent error at
1/2/4/8 plies, rollout error growth, target-mask counts, effective rank and
model/search compute. Stratify by predeclared early/mid/late and
tactical/terminal-adjacent rules. Report value calibration separately for
each of the 16 ordered rollout-policy matchups and for their uniform mixture;
do not call the value head calibrated for any real opponent. Also report
matches against fixed random, tactical, positional and pinned bounded-search
opponents, with seat swaps and the exact opponent code/config hashes. These
opponent-suite results are secondary and do not change the head-to-head
primary metric.

A pass nominates a new confirmatory experiment; it proves no superiority,
equilibrium, exploitability, generalized transfer, novelty or Q1 readiness.
Before confirmation, independently preregister primary metric, sample/power
rationale, paired schedule, multiplicity correction, timeout/censor policy
and stopping rule.

## 8. Preconditions before training and outcome evaluation

The V2.12 research gate must pass primary-source novelty comparison against
JEPA-WM multi-step training, MuZero/AlphaZero, value-aligned world models,
policy-aware simulator learning, and the 2026 next-latent critique. A fresh
trajectory generator must pass transition replay, action/role, mask,
deduplication and split-leak tests. An independent reviewer must accept this
method and the revised no-outcome compute protocol before any fitting.

Narrow feasibility exception: after independent acceptance of v04, implement
only the minimal inference/instrumentation code needed for a random-initialized
no-training compute pilot. It may load synthetic legal root states and measure
rule transitions, model calls, memory, node visits and wall time. It must not
read training/outcome labels, update parameters, save trained checkpoints,
record game scores or select a model. Review this harness and its no-outcome
report before proceeding. This exception does not waive the novelty, data
audit, split/leakage or separate pre-fit review gates for objective/training
code or any fitted experiment.

Only a small adapter feasibility audit has passed: 8x8 Connect Four and
Reversi feature/action shapes, sampled legal transitions, role alternation,
sampled eight-ply checks, and 24 random full episodes per variant (including
eight forced Reversi passes) worked. This does not establish data audit,
training or inference feasibility, planning quality, model performance,
novelty, transfer, or scientific superiority. No V2.12 model/training code or
training dataset has been created.
